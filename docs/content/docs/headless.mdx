Everything on this page runs with **zero React imports**: thumbnails, chart
images, share cards, atlas baking, PDF reports, background tasks. The
imperative layer is the floor the declarative layer stands on — components are
sugar over the same nodes, so the two forms compile byte-for-byte the same
program.

## Build and export

```ts
import { Scene, image, loadImage, rect } from "react-native-tgfx";

const photo = await loadImage("https://picsum.photos/id/237/300/200");

const scene = Scene.create({ width: 320, height: 420 });
scene.add(rect({ x: 0, y: 0, width: 320, height: 420, color: "#101725" }));
scene.add(rect({ x: 10, y: 10, width: 300, height: 60, color: "#ff2d55" }));
scene.add(
  image({ image: photo, x: 10, y: 90, width: 300, height: 200, fit: "cover" })
);

await scene.save(`${dir}/card.png`, { pixelRatio: 2 });
// written natively; bytes never enter JS
```

Every component has a factory (`rect`, `text`, `linearGradient`, `mask`, …) —
see [Imperative](/docs/imperative). `scene.save` picks the format from the
extension (`.png`, `.jpg`, `.webp`) unless `format` overrides it; `toImage`
returns the [`TgfxImage`](/docs/images) instead, and `toSvg` / `toPdf` are the
vector twins:

```ts
const still = await scene.toImage(); // draw it back, encode it, share it
const markup = await scene.toSvg();
await scene.toPdf(`${dir}/card.pdf`);
```

The render size comes from the call's `width`/`height`, else the size
`Scene.create` was given, else a lone attached surface — with none of the
three, the call throws. The `renderToImage` / `renderToSvg` / `renderToPdf`
functions still take a `Scene`, `SceneNode[]` or JSX; PDF pages mix `element`
(JSX) and `scene` freely.

## Mutate without re-encoding

Structural mutations (`add` / `insert` / `remove` / `replaceChildren`) batch
into one compile per microtask. Value mutation goes through handles — the slot
path, no re-encode:

```ts
const counter = createHandle();
scene.add(text({ ref: counter, x: 16, y: 40, text: "Day 1", fontSize: 18 }));

for (const n of [1, 2, 3]) {
  counter.set({ text: `Day ${n}` });
  const img = await renderToImage(scene, { width: 400, height: 400 });
  await img.save(`${dir}/day-${n}.png`);
  img.dispose();
}
```

Handles are for tens of live nodes, not thousands: a handle promotes every
numeric prop to a slot, so 400 handled nodes are thousands of slots walked per
frame. Pools go through buffers — `atlas` + [`createSpriteBuffer`](/api/functions/createSpriteBuffer)
or `vertices` + [`createVertexBuffer`](/api/functions/createVertexBuffer)
scale to 10³–10⁵ where handles stop at 10¹–10².

## Repeated renders: the retained surface

```ts
const surface = createOffscreenSurface({ width: 1024, height: 1024 });
scene.attach(surface); // a surface is a target, like a view
for (let f = 0; f < 120; f++) {
  t.set({ x: f * 4 }); // slot write
  surface.flush(); // render on the offscreen worker
  if (f % 30 === 0) await surface.save(`${dir}/frame-${f}.png`);
}
surface.dispose();
```

See [Export](/docs/snapshots) for the surface's full contract —
`setViewport`, headless `hitTest`, `toImage`.

## Presses without a canvas

```ts
import { dispatchPress } from "react-native-tgfx";

dispatchPress(scene.handlesAt(surface.hitTest(x, y, false)), [
  [box, () => select(box)],
]);
```

Topmost wins, exactly as `useCanvasPress` dispatches on a canvas.

## Clocks, video and camera, callable

Each hook-only API now has a callable form the hook wraps:

```ts
const clock = createClock(); // seconds on the UI thread; clock.value → a uniform
clock.stop();

const player = await createVideoPlayer(require("./clip.mp4"), {
  looping: true,
});
// currentFrame is null until the first decode and is read once at add time —
// build the node when the frame exists:
player.onFrame((frame) =>
  scene.add(image({ image: frame, x: 0, y: 0, width: 1280, height: 720 }))
);
player.setOptions({ paused: true });
player.dispose();

const sink = createCameraFrameSink({ onImage: (img) => attachToScene(img) });
// VisionCamera side: useFrameProcessor((f) => { 'worklet'; sink.push(f) }, [sink])
sink.dispose();
```

## Worklets

Scenes are built on worklet runtimes too. `createScene()` and `sceneFrom()`
are the worklet-callable forms — a class's statics do not cross runtimes, so
`Scene.create` is not. The whole compile graph is workletized: factories,
`add`/`remove`, `attach` and `flush` all run where the worklet runs, and the
program a worklet compiles is byte-identical to the JS thread's.

```ts
const surface = createOffscreenSurface({ width: 1024, height: 1024 });
const boxed = NitroModules.box(surface);

scheduleOnUI(() => {
  "worklet";
  const scene = createScene();
  scene.add(rect({ x: 0, y: 0, width: 512, height: 512, color: "#101725" }));
  scene.attach(boxed.unbox());
  scene.flush();
  boxed.unbox().flush();
  // The runtime that made the scene owns it; its global keeps it alive
  // across worklet invocations. A SharedValue would clone it instead.
  globalThis.myScene = scene;
});
```

What differs from the JS thread:

- `createScene()` / `sceneFrom()`, never the statics.
- Call `scene.flush()` yourself after structural changes — commit batching is
  a microtask affair, and explicit flush is the predictable form inside a
  frame callback.
- The exports (`save`, `toImage`, `toSvg`, `toPdf`) throw by name: render
  into an attached offscreen surface and call `surface.save` / `surface.toImage`
  from the JS thread instead.
- Handles (`createHandle`) and mapper-driven animation stay on the JS thread:
  a worklet scene is structural nodes and literal props, and per-frame motion
  drives `surface.setValues` directly.

A `Scene` attached on the JS thread still drives value slots from the UI
thread by itself when Reanimated is installed — `handle.set()` and
`SharedValue` props repaint with no driver component. A surface is a Nitro
object, so `NitroModules.box()` hands it to any worklet runtime; box the
object and call methods on the unboxed instance — never destructure them.

## Without Reanimated

Factories, `Scene`, every export, `encode`/`save` and the offscreen surface
work with Reanimated absent — pushes come from the JS thread. `createClock`,
`createVideoPlayer` and `createCameraFrameSink` throw without it: their pumps
live on the UI runtime.
