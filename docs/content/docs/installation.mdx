---
title: Installation
description: Every step needed to get a canvas drawing, including the two that are easy to miss.
---

These steps were verified by installing the published package into a fresh React
Native app and running it on a device. Two of them are not obvious, and skipping
either fails — one at build time, one at runtime.

## 1. Install

```bash
npm install react-native-tgfx@alpha react-native-nitro-modules
```

The current release is `0.0.1`, published under the `alpha` dist-tag rather than
`latest`, so the tag is not optional.

## 2. Install Reanimated *and* worklets

```bash
npm install react-native-reanimated react-native-worklets
```

Reanimated 4 moved worklets into their own package. Installing Reanimated alone
fails the Android build during configuration:

```
[Reanimated] `react-native-worklets` library not found. Please install it as a
dependency in your project. Install `react-native-worklets` with your package
manager, i.e. `yarn add react-native-worklets` or `npm i react-native-worklets`.
```

Skip both if nothing in your scene animates — the library loads Reanimated
through a guarded `require`, so its absence is not an error. Any `SharedValue`
prop simply holds its committed value.

## 3. Add the worklets Babel plugin

```js title="babel.config.js"
module.exports = {
  presets: ['module:@react-native/babel-preset'],
  plugins: ['react-native-worklets/plugin'],
}
```

Without it the app builds and installs, then **crashes on the first `<Canvas>`**
with `TypeError: Cannot read property 'bytecode' of undefined`, thrown from
Reanimated's worklets module.

Worklets need this transform to produce their bytecode. The stack points at
`Canvas` and reads like a rendering bug, which is why it is worth stating.

## 4. Build

<Owned by="native">
The first release build compiles tgfx from source — it is a graphics engine, and
on a laptop it took close to fifty minutes. Later builds reuse the compiled
output and take minutes.
</Owned>

```bash
npx react-native run-android
```

The vendored tgfx static library is built for `arm64-v8a` only, so a release
build that includes `x86`/`x86_64` fails at link with `is incompatible with
elf_i386`. Restrict the release variant's `abiFilters` to `arm64-v8a` until
[#139](https://github.com/riteshshukla04/react-native-tgfx/issues/139) is fixed;
that issue also tracks a `Couldn't determine Hermesc location` failure in the
release bundle step.

### iOS

iOS needs one manual step before `pod install`, because the podspec links a
static library that is not shipped in the package:

```bash
bash node_modules/react-native-tgfx/scripts/build-tgfx-ios.sh
```

```bash
cd ios && pod install
```

Set `PLATFORM=OS64` before running it for a device build, and re-run it whenever
the package is updated.

## Optional: the camera

Camera frames need [`react-native-vision-camera`](https://visioncamera.margelo.com)
v5 or newer, plus its worklets package for `useFrameOutput`:

```sh
npm install react-native-vision-camera react-native-vision-camera-worklets
```

`useCameraFrame()` from `react-native-tgfx` is all most apps need — see
[Camera frames](/docs/camera). Nothing extra to install: the frame is typed
structurally, so the core package has no dependency on VisionCamera.

If the frame processor has **no** JS work to do, `react-native-tgfx-vision-camera`
moves the import into a native frame-processor plugin so no frame reaches a JS
runtime at all:

```sh
npm install react-native-tgfx-vision-camera
```

It links the core package's native library directly — an Android prefab, an iOS
pod dependency — so it needs no extra build step of its own beyond the one in
step 4. A screen running a detector every frame cannot use it — see
[face blur](/docs/camera#face-blur) for why.

## 5. Draw something

```tsx title="App.tsx"
import { Canvas, Circle, Group, Rect } from 'react-native-tgfx'

export default function App() {
  return (
    <Canvas style={{ width: 300, height: 140 }}>
      <Rect x={0} y={0} width={300} height={140} color="#101725" />
      <Circle cx={70} cy={70} r={44} color="#d98a4a" />
      <Circle cx={70} cy={70} r={44} color="#f2c088" style="stroke" strokeWidth={3} />
      <Group transform={[{ rotate: '12deg' }]}>
        <Rect x={140} y={34} width={72} height={72} color="#6aa9ff" />
      </Group>
    </Canvas>
  )
}
```

## If the canvas is blank

A blank canvas in a running app means the JavaScript resolved and the native
library did not. On Android, check it is actually in the APK:

```bash
unzip -l android/app/build/outputs/apk/release/app-release.apk | grep NitroTgfx
```

You should see `lib/arm64-v8a/libNitroTgfx.so`. A build can succeed with that
file missing, so check directly rather than trusting a green build.
