## 1. Install

```bash
npm install react-native-tgfx@alpha react-native-nitro-modules
```

tgfx ships prebuilt per ABI (Android archive, iOS `xcframework`). No postinstall
step.

Also install `react-native-reanimated` and `react-native-worklets` — required
for animated, camera-frame and video paths; skip if nothing animates.

## 2. Build

```bash
npx react-native run-android
```

```bash
cd ios && pod install
```

## 3. Draw

```tsx title="App.tsx"
import { Canvas, Circle, Group, Rect } from 'react-native-tgfx'

export default function App() {
  return (
    <Canvas style={{ width: 300, height: 140 }}>
      <Rect x={0} y={0} width={300} height={140} color="#101725" />
      <Circle cx={70} cy={70} r={44} color="#d98a4a" />
      <Circle cx={70} cy={70} r={44} color="#f2c088" style="stroke" strokeWidth={3} />
      <Group transform={[{ rotate: '12deg' }]}>
        <Rect x={140} y={34} width={72} height={72} color="#6aa9ff" />
      </Group>
    </Canvas>
  )
}
```

## Vulkan backend (Android, optional)

The Android renderer runs on OpenGL ES by default. To render through Vulkan
instead, add one line to your app:

```properties title="android/gradle.properties"
TgfxVulkan=ON
```

Vulkan prebuilts for all four ABIs ship in the package, so this is the whole
switch — no extra scripts, no source build. On a GPU-bound scene expect
noticeably higher frame rates at lower CPU cost; see
[the performance page](/docs/performance#vulkan-backend-android-experimental)
for measured numbers and caveats.

## Native binary check

The JavaScript writer and C++ reader share a scene version. After that version
changes, an `unexpected header` warning or blank canvas means the installed APK
still contains the old native reader, so rebuild the app. To inspect a release
APK directly:

```bash
unzip -l android/app/build/outputs/apk/release/app-release.apk | grep NitroTgfx
```

The packaged Android build contains one `lib/<abi>/libNitroTgfx.so` for each of
`arm64-v8a`, `armeabi-v7a`, `x86` and `x86_64`.
