The drawing primitives and the paint that fills them. The larger topics live on
their own pages: [text](/docs/text), [images](/docs/images),
[blend modes and filters](/docs/effects), and
[snapshots and export](/docs/snapshots).

## Canvas

The root. Everything else must be a descendant.

```tsx
import { Canvas, Rect } from 'react-native-tgfx'

function Panel() {
  return (
    <Canvas style={{ width: 300, height: 140 }}>
      <Rect x={0} y={0} width={300} height={140} color="#101725" />
    </Canvas>
  )
}
```

| prop | type | default |
| --- | --- | --- |
| `style` | view style | — |
| `composite` | `'layer' \| 'texture'` | `'layer'` |
| `opaque` | `boolean` | `false` |
| `debug` | `boolean` | `false` |

`composite: 'layer'` punches through the window: React Native content *behind*
the canvas does not show through its transparent pixels, and view transforms do
not apply to it. Use `'texture'` when the canvas has to compose with views
behind it or be transformed.

Children draw in document order — later siblings paint over earlier ones.

A `ref` on `<Canvas>` gives a `CanvasHandle` for reading pixels back — see
[snapshots and export](/docs/snapshots).

## Shapes

| component | props |
| --- | --- |
| `Rect` | `x`, `y`, `width`, `height` |
| `RoundedRect` | `x`, `y`, `width`, `height`, `r`, or `rx`/`ry` to override `r` per axis |
| `Oval` | `x`, `y`, `width`, `height` |
| `Circle` | `cx`, `cy`, `r` |
| `Line` | `x1`, `y1`, `x2`, `y2` |
| `Path` | `path` — SVG path data, `string`; plus `start`, `end`, `fillType` and the path effects below |
| `Image` | `image`, `x`, `y`, `width`, `height`, `fit`, `sampling`, `rect` — see [images](/docs/images#image) |
| `Atlas` | `image`, `sprites`, `sampling` — many sprites from one sheet in one node, see below |
| `Vertices` | `vertices`, `colors`, `textures`, `indices`, `mode` — a raw triangle mesh, see below |
| `Text` | `text`, `x`, `y`, plus the font and paragraph props — see [text](/docs/text) |
| `TextPath` | `path`, `text`, `startOffset`, plus the font props — see [text](/docs/text) |
| `Fill` | none of its own — covers the canvas |

Every geometric prop above is `Animated<number>`, so it may be a plain number or
a Reanimated `SharedValue`. The exceptions are `path`, `text` and `fontFamily`
(plain `string` — there is no value slot for a string, so a `SharedValue` there
would never animate), `image` (a native handle from
[`useImage`](/docs/images#useimage)), and the `fit`/`sampling`/`rect` enums.

`Text.fontSize` defaults to `14`. All of these take the paint props below.

### Line ignores `style`

A line has no interior, so it is always stroked. Passing `style="fill"` to
`<Line>` still draws a stroke.

### Fill

`Fill` has no geometry of its own but takes every paint prop and accepts
children, which makes it the natural host for a shader:

```tsx
import { Canvas, Fill, Shader } from 'react-native-tgfx'

const source = `
uniform float2 uSize;
half4 main(float2 pos) {
  float2 uv = pos / uSize;
  return half4(uv.x, uv.y, 0.6, 1.0);
}
`

function Backdrop({ width, height }: { width: number; height: number }) {
  return (
    <Canvas style={{ width, height }}>
      <Fill>
        <Shader source={source} uniforms={{ uSize: [width, height] }} />
      </Fill>
    </Canvas>
  )
}
```

Coverage comes from the device-space clip, so a transform on an enclosing
`Group` moves the paint but not the area filled — as in Skia.

### Path effects

`<Path>` can trim itself, dash itself, and round its own corners. Trim is the
line-drawing animation: `start` and `end` are 0-1 along the path and both are
animatable, so a `SharedValue` on `end` draws the path on.

```tsx
import { DashPathEffect, Path } from 'react-native-tgfx'

<Path path={route} style="stroke" strokeWidth={4} end={progress}>
  <DashPathEffect intervals={[10, 5]} phase={march} />
</Path>
```

| prop | what it does |
| --- | --- |
| `start`, `end` | the segment to keep, 0-1. `end` below `start` reverses it |
| `fillType` | `'winding'` (default) or `'evenOdd'` |
| `<DashPathEffect>` | `intervals` — alternating on/off lengths, even count; `phase` — offset, animatable |
| `<CornerPathEffect>` | `r` — corner radius, applied before any stroke |

Trim is applied first — react-native-skia bakes it into the path the same way —
then corner, then dash. So a dash pattern re-flows as a trim shortens the path
rather than staying pinned in place.

`intervals` needs an even count of at least two; anything else is skipped and the
path draws solid, with a warning in dev.

Only what actually moves is re-run. The longest static run of effects is baked
into the path once at commit, so a static trim in front of a marching dash costs
nothing per frame. The exception is an animated `start`/`end`: trim runs first,
so anything after it has to run again too — pairing a moving trim with a
`<CornerPathEffect>` on a long path is by far the most expensive combination
here, and a rounded path you trim is cheaper drawn as a pre-rounded `path`.

### Atlas

`<Atlas>` draws N sprites cut from one image from a **single node**. N `<Image>`
nodes cost N host nodes, N paint resolutions and ~15 wire words each; an atlas is
one node, one paint, and seven words per sprite, which is what makes tile maps
and particle fields affordable. (The GPU work is the same either way — tgfx
already merges consecutive draws of one image into one batched op.)

```tsx
import { Atlas, Canvas, useImage } from 'react-native-tgfx'

const sheet = useImage(require('./sprites.png'))

<Canvas style={{ flex: 1 }}>
  {sheet != null && (
    <Atlas
      image={sheet}
      sprites={particles.map((p) => ({
        rect: { x: 0, y: 0, width: 16, height: 16 },
        x: p.x,
        y: p.y,
        scale: p.size,
      }))}
    />
  )}
</Canvas>
```

Each sprite takes a `rect` — its box in the sheet, in image pixels — and an
`x`/`y` naming where the sprite's **centre** lands on the canvas, plus an
optional uniform `scale`. The `rect` must lie inside the sheet: tgfx clips one
that runs past the edge, and the clipped sprite is drawn smaller and off its
stated centre.

Sprites are placed axis-aligned. tgfx's `drawAtlas` maps each sprite's bounding
box, so a per-sprite rotation would stretch the sprite rather than turn it, and
the prop is not offered rather than being offered and ignored. Rotate a `<Group>`
around the whole batch, or fall back to one `<Image>` per sprite when each needs
its own angle. Per-sprite tint colours are missing for the same reason: tgfx
applies them only to an alpha-only atlas.

The `sprites` array is read when the scene compiles, so moving a particle field
means a React render. A worklet-driven bulk update is tracked separately.

### Vertices

`<Vertices>` draws an arbitrary triangle mesh — the one component that works
below the shape level. Mesh gradients, image warping, and quads you build
yourself all live here.

```tsx
import { Canvas, Vertices } from 'react-native-tgfx'

<Canvas style={{ flex: 1 }}>
  <Vertices
    vertices={[
      { x: 0, y: 0 },
      { x: 200, y: 0 },
      { x: 0, y: 200 },
      { x: 200, y: 200 },
    ]}
    colors={['#ff0000', '#00ff00', '#0000ff', '#ffff00']}
    indices={[0, 1, 2, 1, 2, 3]}
  />
</Canvas>
```

`vertices` are canvas points. `colors`, if given, are one per vertex and are
interpolated across each triangle — that is the whole mesh-gradient trick.
`indices` reuse vertices so a shared edge is stored once; without them the
vertices are taken in order. `mode` is `'triangles'` (default, three vertices per
triangle) or `'triangleStrip'` (each new vertex closes a triangle with the
previous two). Skia's `'triangleFan'` has no tgfx topology and is not offered.

`textures` are one coordinate per vertex, in the **pixels** of the image behind
an `<ImageShader>` on the same node — that is how you warp an image across a
mesh. Without a shader they do nothing.

An attribute array shorter than `vertices` is dropped rather than padded, and a
longer one is truncated: the reader takes exactly one entry per vertex, so a
partial block would put it out of step with the rest of the program.

Every index must point at a vertex that exists. One that does not skips the whole
mesh — nothing below this layer range-checks them, so an index past the end would
sample another draw's buffer. An indexed mesh is also capped at 65536 vertices;
past that it draws nothing. Both warn in dev.

Like `<Atlas>`, the arrays are read when the scene compiles, so a moving mesh
means a React render — a Reanimated shared value inside `vertices` is frozen at
its last commit.

How the colour is resolved follows tgfx: a shader with per-vertex colours
multiplies the two; a shader alone gives the texture colour; per-vertex colours
alone give the vertex colour; neither gives the paint colour. A solid
`<ColorShader>` is folded into the paint colour before any of that, so per-vertex
colours replace it rather than multiplying with it.

## Paint

Set directly on a shape, or inherited from a `<Paint>` child:

```tsx
import { Circle, Paint } from 'react-native-tgfx'

<Circle cx={70} cy={70} r={40}>
  <Paint color="#f2c088" style="stroke" strokeWidth={3} />
</Circle>
```

| prop | type | default |
| --- | --- | --- |
| `color` | `Animated<Color>` — hex, `rgb()`/`rgba()`, `hsl()`/`hsla()`, or a named colour | black |
| `style` | `'fill' \| 'stroke'` | `'fill'` |
| `strokeWidth` | `Animated<number>` | `1` |
| `strokeCap` | `'butt' \| 'round' \| 'square'` | `'butt'` |
| `strokeJoin` | `'miter' \| 'round' \| 'bevel'` | `'miter'` |
| `strokeMiter` | `number` — past this length-over-width ratio a `'miter'` join bevels | `4` |
| `opacity` | `Animated<number>` | `1` |
| `antiAlias` | `boolean` | `true` |
| `blendMode` | `BlendMode` | `'srcOver'` |

A `<Paint>` inside a `<Group>` sets the inherited default for descendants; inside
a shape it overrides that shape only, including its `opacity`.

To stroke *and* fill one shape, draw it twice — one fill, one stroke. That is
what the engine does anyway.

### Background colour

A `backgroundColor` in the canvas's `style` is drawn as the first thing in the
scene, because the platform view cannot always show it: on Android the canvas is
a SurfaceView, which punches a hole through the window it sits in. The colour is
cleared off the view at the same time, so it is painted once on every platform.

It is drawn exactly as `<Fill color={...}>` would be, so it must be a colour
string `<Fill>` accepts — `#rgb`, `#rrggbb`, `#rrggbbaa`, `rgb()`, `rgba()`,
`hsl()` or a CSS name. A `PlatformColor()`, a `processColor()` number, or
`'transparent'` is left to the platform view untouched, which on Android means
it will not appear behind the canvas; draw those with `<Fill>` instead.

## Group

Applies transforms and inherited paint to its children.

```tsx
import { Group, Rect } from 'react-native-tgfx'

<Group transform={[{ translate: [40, 0] }, { rotate: '12deg' }, { scale: 1.5 }]}>
  <Rect x={0} y={0} width={40} height={40} />
</Group>
```

| prop | type |
| --- | --- |
| `transform` | `Transform[]` |
| `origin` | `Vector` — `{ x, y }`, the point transforms are applied about |
| `clip` | `{ x, y, width, height, r?, rx?, ry? }` or SVG path data |
| `invertClip` | `boolean` — keep what falls outside `clip` instead of inside |
| `layer` | `boolean` — composite the subtree once, offscreen |

Operations apply in array order. The full set is `translate`, `translateX`,
`translateY`, `scale`, `scaleX`, `scaleY`, `rotate`, `rotateZ`, `skewX`, `skewY`.

Rotations accept a string with a `deg` or `rad` suffix. A bare number is
radians — and an **animated** rotation is always radians, because a `SharedValue`
carries no unit. Convert in your worklet if you are thinking in degrees.

When no operand is animated the matrix is folded at compile time and costs
nothing per frame. One animated operand moves the whole group onto the per-frame
path — worth knowing when a static group sits inside an animated one.

### Clipping

`clip` confines the subtree. Give it a rect, add `r` (or `rx`/`ry`) for a rounded
one, or hand it SVG path data for anything else. `invertClip` keeps the
complement instead — a spotlight cut out of a dim overlay is `clip` plus
`invertClip`.

```tsx
<Group clip={{ x: 0, y: 0, width: 100, height: 100, r: 12 }}>
  <Image x={0} y={0} width={100} height={100} image={photo} />
</Group>
```

Like `<Path path>`, `clip` is read once per commit — a `SharedValue` there would
never animate.

A rect or rounded-rect clip is free: the GPU scissors it, with no offscreen. A
path clip rasterises a mask per group per frame, which is far more expensive.
`invertClip` moves a rect into that second class too, because an inverse fill
only exists on a path — so invert a rect clip when you want the effect, not out
of habit.

### Layers

By default a group's `opacity` multiplies into each child, so two overlapping
children blend twice and the overlap reads darker than either one. `layer`
composites the whole subtree once into an offscreen and applies the opacity to
the result, which is what you usually mean:

```tsx
<Group layer opacity={0.5}>
  <Circle cx={40} cy={40} r={30} color="#4F8EF7" />
  <Circle cx={70} cy={40} r={30} color="#4F8EF7" />
</Group>
```

That offscreen costs a render target, so reach for it when the double-blend is
visible, not by default.

### Recording a static subtree

`<Group picture>` records its subtree once and replays the recording every frame
— for the parts of a scene that redraw constantly but never change, like a map
background or a chart's grid and axes.

```tsx
<Group picture>
  <Path path={gridPath} color="#e5e5ea" style="stroke" />
  {ticks.map((t) => (
    <Text key={t.at} x={t.x} y={h} text={t.label} fontSize={11} />
  ))}
</Group>
```

The flag is **ignored, with a warning, if anything under it changes between
frames** — an animated value, a `<CameraFrame>`, an `<Image>` on a video handle,
or one whose decode has not arrived yet. A recording would freeze those. The
check runs in the reader, which is the only place that can see all of them: a
shared value used twice in a scene is written once, and an image handle is a
plain integer with no hint of what backs it.

One such child opts the entire group out, so split the moving parts into a
sibling group to keep the static ones recorded.

What it replays is the recorded draw calls, not rasterized pixels — tgfx still
builds and tessellates every op each frame. Measured on 125-500 nodes of real
geometry that is **roughly 10-15% of frame CPU**, rising towards 50% on many
simple shapes. It is a way to trim a static background, not a step change, and
it does not reduce allocations.

The recording is rebuilt whenever the scene recommits, so it costs one frame
after any React render that changes the tree. It composes with `clip` and
`layer` on the same group.

## Shader composition

`<Blend>` folds its shader children together with a blend mode, left to right:
the first child is the destination and each next one blends over it.
`<ColorShader>` is the leaf that makes a solid colour usable as an input.

```tsx
import { Blend, ColorShader, RadialGradient, Rect, Turbulence } from 'react-native-tgfx'

<Rect x={0} y={0} width={256} height={256}>
  <Blend mode="multiply">
    <RadialGradient center={{ x: 128, y: 128 }} r={128} colors={['blue', 'yellow']} />
    <Turbulence freqX={0.05} freqY={0.05} octaves={4} />
  </Blend>
</Rect>
```

Nesting is allowed: a `<Blend>` can be a child of another `<Blend>`. A child that
resolves per frame — an animated `<Shader>` uniform, or a `<ImageShader>` on a
video or camera handle — keeps doing so inside the fold; only a tree of entirely
static children is folded once at commit.

## Gradients and noise

Children of a shape or `<Paint>`. They draw nothing on their own.

| component | props |
| --- | --- |
| `LinearGradient` | `start`, `end`, `colors`, `positions` |
| `RadialGradient` | `center` (or `cx`/`cy`), `r`, `colors`, `positions` |
| `SweepGradient` | `c` (or `center`, or `cx`/`cy`), `start`, `end`, `colors`, `positions` |
| `DiamondGradient` | same props as `RadialGradient` |
| `FractalNoise` | `freqX`, `freqY`, `octaves`, `seed` |
| `Turbulence` | same props as `FractalNoise` |
| `Shader` | `source`, `uniforms` — see [shaders](/docs/shaders) |
| `ImageShader` | `image`, `tx`, `ty`, `sampling`, `rect`, `fit` — see [images](/docs/images#imageshader) |
| `Blend` | `mode` — folds its shader children, see [above](#shader-composition) |
| `ColorShader` | `color` |

`colors` is `Color[]` and `positions` is `number[]`. `SweepGradient`'s `start`
and `end` are **degrees**, as in Skia, defaulting to a full 0–360 turn. Noise
defaults are `freqX` and `freqY` `0.05`, `octaves` `1`, `seed` `0`.

Gradient geometry (`start`, `end`, `center`, `r`), `positions`, `colors` and all
noise parameters are read once at commit and do not animate.

```tsx
import { LinearGradient, Rect } from 'react-native-tgfx'

<Rect x={0} y={0} width={300} height={140}>
  <LinearGradient
    start={{ x: 0, y: 0 }}
    end={{ x: 300, y: 0 }}
    colors={['#d98a4a', '#6aa9ff']}
  />
</Rect>
```

## Hooks

### useClock

Returns a `SharedValue<number>` holding **seconds** since the first frame,
written on the UI thread. See [animation](/docs/animation).

The image and font hooks live with their subjects: [`useImage`, `useImageState`,
`imageFromNativeBuffer` and `setImageCacheLimit`](/docs/images#hooks), and
[`useFonts` and `measureText`](/docs/text#usefonts).

## Escape hatch

`TgfxNativeView` is exported for callers who want to drive the native view
directly — pushing a `scene` buffer and a values buffer themselves rather than
going through `<Canvas>`. Its ref type is `TgfxViewRef`. Most code should not
need it.

## What is not supported

- No clipping primitive is exposed.
- No `ImageSVG`: SVG documents are not parsed, only single path data strings.
- No child shaders — `uniform shader` is rejected at compile time. See
  [shaders](/docs/shaders).
- Colours, paths, text, images, gradient geometry, noise and filter parameters
  do not animate. See [animation](/docs/animation).
- A filter on a `<Group>` applies per descendant, not to the group as one layer.
- Blend modes that need a canvas read-back do not render on the iOS Simulator.
- No bidi reordering or complex-script shaping in text: Arabic, Hebrew and the
  Indic scripts lay out in logical order with unshaped glyphs.
- No styled runs inside one paragraph, no `Glyphs`, and no text-as-path exposed
  to JS.
