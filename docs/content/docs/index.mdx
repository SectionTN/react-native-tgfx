Draw shapes, paths, text, images and runtime shaders with React components. The
scene compiles to a binary buffer the native renderer executes on its own thread.

```tsx
import { Canvas, Circle, Rect } from 'react-native-tgfx'

<Canvas style={{ width: 300, height: 140 }}>
  <Rect x={0} y={0} width={300} height={140} color="#101725" />
  <Circle cx={70} cy={70} r={44} color="#d98a4a" />
</Canvas>
```

## The one idea worth knowing first

A canvas library has to get your drawing across to the renderer. The
straightforward way is to rebuild and re-send it whenever anything changes —
which means an animation rebuilds it on every frame, on the thread your app's
logic runs on.

This library splits it in two. Static structure is compiled once. Values that
move are written as *slots* — positions in a flat array the native side patches
directly, on the UI thread, without waking JavaScript.

<Owned by="js">
Compiling the scene: walking your React children, packing them into a buffer,
interning strings. Happens when the tree **changes**, not when a value changes.
</Owned>

<Owned by="native">
Resolving slots and drawing: reading the patched values and issuing GPU work.
Happens every frame, and JavaScript is not involved.
</Owned>

That split is why a `SharedValue` driving `x`, `opacity`, `strokeWidth` or a
shader uniform needs no JavaScript work per frame — and it is the thing to keep
in mind when a prop unexpectedly refuses to animate. See
[animation](/docs/animation).

## What you get

- **Shapes and paths** — rect, rounded rect, oval, circle, line, SVG path data.
- **Text and images** with a font family and a fit mode.
- **Paint as a component** — fill or stroke, caps, joins, opacity, anti-aliasing,
  inherited down a `<Group>`.
- **Gradients and noise** — linear, radial, sweep, diamond, fractal noise,
  turbulence.
- **Runtime shaders** in SkSL, with uniforms that animate on the UI thread.

## Where it fits

Scenes that draw a lot and animate continuously: data visualisation, generative
backgrounds, custom controls — anything where you would otherwise reach for a
native view per element.

Said plainly: memory use is its strongest characteristic, frame delivery is
solid, and total CPU is not yet where it should be against the best alternative.
That gap is open as
[issue #24](https://github.com/riteshshukla04/react-native-tgfx/issues/24), and
[performance](/docs/performance) has the harness to measure your own scene.

## Status

Alpha, published as `0.0.1` under the `alpha` tag. It has been installed from
npm into a fresh app and verified drawing on a device — see
[installation](/docs/installation), which documents the two setup steps that are
easy to miss. iOS still needs a manual build step.
