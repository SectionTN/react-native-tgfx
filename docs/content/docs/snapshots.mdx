## Snapshot a live canvas

```tsx
const canvas = useRef<CanvasHandle>(null)

async function exportCanvas() {
  if (canvas.current == null) return
  const shot = await canvas.current.snapshot()   // Snapshot
  await canvas.current.save('/absolute/path/out.png')
}
```

[`snapshot`](/api/interfaces/CanvasHandle) returns a [`Snapshot`](/api/interfaces/Snapshot):
PNG/JPEG/WebP bytes, or straight-alpha RGBA8888 rows for `format: 'raw'`, in an
`ArrayBuffer` rather than base64. iOS wraps the native result without a copy;
Android copies the temporary JNI buffer into a Nitro-owned `ArrayBuffer` once.
`save` encodes and writes natively, so the bytes never enter JS.

[`SnapshotOptions`](/api/interfaces/SnapshotOptions) · [`SnapshotFormat`](/api/type-aliases/SnapshotFormat)

### Colour

An encoded readback carries the surface's colour profile, so a
`colorSpace="display-p3"` canvas produces a P3-tagged PNG rather than P3 numbers
labelled sRGB. `scale` goes through a second surface and now carries the space
with it — before, a scaled readback lost the profile a scale-1 one kept.

## Offscreen

[`renderToImage`](/api/functions/renderToImage) renders a scene with no canvas
mounted ([`RenderToImageOptions`](/api/interfaces/RenderToImageOptions)). It —
like `renderToSvg` and `renderToPdf` — takes JSX, a `SceneNode[]` from the
element factories, or a [`Scene`](/api/classes/Scene); the non-JSX forms never
construct a reconciler:

<Tabs items={['Declarative', 'Imperative']}>
<Tab value="Declarative">

```tsx
const image = await renderToImage(
  <Rect x={0} y={0} width={512} height={512}>
    <LinearGradient start={{ x: 0, y: 0 }} end={{ x: 512, y: 512 }} colors={['#f0f', '#0ff']} />
  </Rect>,
  { width: 512, height: 512 }
)
```

</Tab>
<Tab value="Imperative">

```ts
const image = await renderToImage(
  [
    rect({ x: 0, y: 0, width: 512, height: 512 }, [
      linearGradient({ start: { x: 0, y: 0 }, end: { x: 512, y: 512 }, colors: ['#f0f', '#0ff'] }),
    ]),
  ],
  { width: 512, height: 512 }
)

// Or a retained Scene — live handle writes are baked at their current values,
// so mutate-and-export loops re-render without rebuilding the tree:
counter.set({ text: `Day ${n}` })
const still = await renderToImage(scene, { width: 400, height: 400 })
```

</Tab>
</Tabs>

`renderToPdf` pages carry either `element` (JSX) or `scene` (nodes or a
`Scene`), mixed freely.

## Retained surface

[`createOffscreenSurface`](/api/functions/createOffscreenSurface) keeps a GPU
surface and its compiled program alive between renders — the
iterate-and-export loop `renderToImage` would pay full price for every time
(surface allocation, program compile, synchronous readback, per call):

```ts
const surface = createOffscreenSurface({ width: 1024, height: 1024 })
scene.attach(surface)                 // a surface is a scene target, like a view

for (let f = 0; f < 120; f++) {
  t.set({ x: f * 4 })                 // slot write — no re-encode
  surface.flush()                     // render on the offscreen worker
  if (f % 30 === 0) await surface.save(`${dir}/frame-${f}.png`)
}
const still = await surface.toImage() // readback only when asked
surface.dispose()                     // GPU memory is explicit-lifetime
```

It speaks the view's `setScene`/`setValues` contract, so `Scene.attach`, node
handles and the Reanimated drivers work unchanged, and it boxes with
`NitroModules.box()` for worklet runtimes. `setViewport([zoom, x, y])` crops
and zooms an export; `hitTest(x, y, precise)` answers headless from the staged
scene. The colour space is a creation option — like a view, a surface cannot
change space after it exists. For a single export, `renderToImage` remains the
cheaper call.

`colorSpace` picks the offscreen surface's space, exactly as the prop does for
a `<Canvas>`, and the result carries it:

```tsx
const wide = await renderToImage(<Chart data={data} />, {
  width: 512,
  height: 512,
  colorSpace: 'display-p3',
})
```

Match it to the canvas the image is headed for. The tag is what makes drawing it
later a *conversion* rather than a reinterpretation — an untagged image is taken
for whatever space it lands in, so a P3 render dropped on an sRGB canvas would
keep its numbers and change its colours.

[`useOffscreenImage`](/api/functions/useOffscreenImage) is the hook form, re-run
on a dependency change:

```tsx
const badge = useOffscreenImage(<Badge count={n} />, { width: 64, height: 64 }, [n])
```
