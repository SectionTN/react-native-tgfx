`<Shader>` takes SkSL source and a set of uniforms, and runs it per pixel on the
GPU. A `<Shader>` is a paint child, so it needs a shape to paint — `<Fill>`
covers the whole canvas and is the usual host.

Here is the whole file, with nothing left out:

```tsx
import { Canvas, Fill, Shader } from 'react-native-tgfx'

const source = `
uniform float2 uSize;
half4 main(float2 pos) {
  float2 uv = pos / uSize;
  return half4(uv.x, uv.y, 0.6, 1.0);
}
`

export function Gradient() {
  return (
    <Canvas style={{ width: 300, height: 140 }}>
      <Fill>
        <Shader source={source} uniforms={{ uSize: [300, 140] }} />
      </Fill>
    </Canvas>
  )
}
```

That paints a 300×140 gradient: red rising left to right, green rising top to
bottom, a constant 0.6 of blue, fully opaque — so black-ish in the top-left
corner through to yellow-white in the bottom-right.

The `[300, 140]` passed to `uSize` is the canvas size in **layout points**,
repeated because the shader has no way to ask how big the shape is. Keeping the
two in sync is the caller's job; the section on
[`pos` units](#the-contract) below is where that usually goes wrong.

## The contract

- The entry point is `main`, returning `half4`, `float4` or `vec4`, taking an
  optional `float2`/`half2`/`vec2` position parameter.
- `pos` arrives in **layout points** — the same units the shape is laid out in,
  not a 0..1 uv and not device pixels. The native side scales the canvas by the
  display density before drawing, so pass your sizes straight through. Scaling
  them by `PixelRatio.get()` makes every uniform too large by that factor, and
  the effect then covers only a fraction of the shape.
- Uniform types: `float`, `float2`, `float3`, `float4`, their `half` and `vec`
  spellings, `int`, and the square matrices `float2x2`, `float3x3`, `float4x4`.
  Each component is one number, so a `float3x3` takes nine.

## Animating a uniform costs nothing per frame

A uniform component may be a `SharedValue`. It becomes a slot, patched on the UI
thread like any other animated value:

```tsx
import { Canvas, Fill, Shader, useClock } from 'react-native-tgfx'

const source = `
uniform float2 uSize;
uniform float uTime;
half4 main(float2 pos) {
  float2 uv = pos / uSize;
  return half4(half(0.5 + 0.5 * sin(uTime + uv.x * 6.0)), half(uv.y), 0.6, 1.0);
}
`

export function Pulse({ width, height }: { width: number; height: number }) {
  const t = useClock()
  return (
    <Canvas style={{ width, height }}>
      <Fill>
        <Shader source={source} uniforms={{ uTime: t, uSize: [width, height] }} />
      </Fill>
    </Canvas>
  )
}
```

<Owned by="native">
Changing a uniform value does **not** recompile the shader program. The compiled
program is keyed on the source text and the uniform names and sizes — never on
their values — so a clock-driven uniform reuses the same program every frame and
only the uniform data changes.
</Owned>

A vector uniform can mix animated and static components: `uniforms={{ uAt: [x, 9] }}`
where `x` is a `SharedValue` allocates one slot and writes `9` as a literal.

## The supported subset

The transpiler translates SkSL to GLSL ES. The gaps are deliberate:

| feature | supported | note |
| --- | --- | --- |
| `main` returning `half4`/`float4`/`vec4` | yes | position parameter optional |
| scalar, vector, `int` and matrix uniforms | yes | up to `float4x4` |
| loops with constant bounds | yes | passed through verbatim |
| declarations above `main` | yes | helpers, `const`, `struct` — see below |
| declarations below `main` | **no** | throws at commit |
| array uniforms | **no** | `uniform float w[5]` throws at commit |
| `uniform shader` | yes | one shader child per declaration — see below |
| `sample(child, coord)` | yes | the same thing as `child.eval(coord)` |

An array uniform and anything declared after `main` throw in JavaScript when the
scene is encoded, as does a `uniform shader` with no matching child. Anything the
transpiler passes through that the GPU then rejects fails later, in the driver,
at draw time — which usually surfaces as a shape that simply does not paint.

When that happens the driver's message is logged under the tag `tgfx`, at ERROR
level — logcat on Android, the Xcode console on iOS. The wording differs by
backend: Android's OpenGL path says `Could not compile shader`, while iOS cross-
compiles the GLSL first, so it says `GLSL to SPIR-V compilation error` and then
`Metal pipeline creation error: vertex or fragment function is nil`.

## Helper functions

Declare them above `main` and call them as you would anywhere else:

```tsx
const source = `
uniform float2 uOrigin;
uniform float2 uSize;

float sdCircle(float2 p, float r) {
  return length(p) - r;
}

half4 main(float2 pos) {
  float2 local = pos - uOrigin - uSize * 0.5;
  float d = sdCircle(local, min(uSize.x, uSize.y) * 0.35);
  float edge = 1.0 - smoothstep(-1.5, 1.5, d);
  return half4(half3(0.15, 0.55, 0.95) * edge, edge);
}
`
```

<Owned by="native">
GLSL ES has no nested functions, so a helper cannot ride inside the body the
engine wraps in its entry point. The transpiler lifts *everything* above `main`
into a separate *preamble* that native emits at file scope, ahead of the entry
point, and renames each name declared there to one mangled per fragment
processor. Two shaders drawn in one scene may therefore both declare a `tint`
without colliding, and the compiled-program key covers the preamble as well as
the body, so they never share a program either.
</Owned>

Everything above `main` moves together, which is what lets a helper read a
top-level `const` or take a top-level `struct` — leaving those behind in the
body would put them out of the helper's scope. Helpers may call each other, and
a name is yours: the mangling is invisible to the source you write.

Declare one name per statement (`const float A = 1.0, B = 2.0;` throws), and
declare it *above* `main` — a helper written below the entry point throws rather
than being silently dropped:

```
[tgfx] shader: declarations must come before main(), found after it: '...'
```

## Child shaders

A `uniform shader` is a slot for another shader. Declare one, pass a shader
component as a child of `<Shader>`, and sample it with `child.eval(coord)` — or
`sample(child, coord)`, which means exactly the same thing.

Children are matched to declarations **by order**, not by name. One child per
declaration, or the commit throws.

Here is the whole file, with nothing left out. It reads a bundled image through a
shader that pushes the red channel sideways, a chromatic-aberration split:

```tsx
import { Canvas, Fill, ImageShader, Shader, useImage } from 'react-native-tgfx'

const source = `
uniform shader img;
uniform float uShift;

half4 main(float2 pos) {
  half4 base = img.eval(pos);
  half4 red = img.eval(pos + float2(uShift, 0.0));
  half4 blue = sample(img, pos - float2(uShift, 0.0));
  return half4(red.r, base.g, blue.b, base.a);
}
`

export function Aberration() {
  const image = useImage(require('./photo.jpg'))
  if (image == null) {
    return null
  }
  return (
    <Canvas style={{ width: 300, height: 200 }}>
      <Fill>
        <Shader source={source} uniforms={{ uShift: 4 }}>
          <ImageShader
            image={image}
            fit="cover"
            rect={{ x: 0, y: 0, width: 300, height: 200 }}
          />
        </Shader>
      </Fill>
    </Canvas>
  )
}
```

`pos` is in layout points, the same units the shape is laid out in, and the child
is sampled in that same space — so `img.eval(pos)` draws the child exactly where
it would have drawn itself, and adding four to `pos.x` moves the sample four
points to the right.

A child is a shader, not an image slot: a gradient, a noise shader, or another
`<Shader>` all work, and nest. Again in full:

```tsx
import { Canvas, Fill, LinearGradient, Shader } from 'react-native-tgfx'

const banded = `
uniform shader ramp;

half4 main(float2 pos) {
  half4 c = sample(ramp, pos);
  float band = step(0.5, fract(pos.y / 12.0));
  return half4(c.rgb * half(0.45 + 0.55 * band), c.a);
}
`

export function Banded() {
  return (
    <Canvas style={{ width: 300, height: 200 }}>
      <Fill>
        <Shader source={banded}>
          <LinearGradient
            start={{ x: 0, y: 0 }}
            end={{ x: 300, y: 0 }}
            colors={['#2b6cff', '#ff3b6b']}
          />
        </Shader>
      </Fill>
    </Canvas>
  )
}
```

That paints the blue-to-red ramp across the canvas, dimmed to 45% in 6-point
horizontal bands repeating every 12 points.

Getting the count wrong throws in JavaScript at commit time rather than painting
nothing on device:

```
[tgfx] shader: the source declares 1 'uniform shader' (img) but 0 shader children
were given — pass one shader child per declaration, in order
```

A child may only be used through `eval`/`sample`. Naming it anywhere else throws
too, because there is no value behind the name to pass around.

<Owned by="native">
Each child becomes a fragment processor registered on the runtime shader's own
processor, and the engine emits one wrapper function per child at file scope,
ahead of your source, so `main` and your helpers can both call it. The name is
mangled per child *and* per processor, so neither two children of one shader nor
two shaders in one scene — nor a shader nested inside another — can collide.

The bridge between your coordinates and the child's is a matrix uniform, uploaded
per draw. It has to be: a texture child samples in normalised texture space, and
the normalisation is only known once the texture is resolved. Nothing is
recompiled for it, and nothing is copied — a child backed by an image samples that
image's existing texture, including a multi-plane YUV hardware buffer, which is
converted by the sampler inside the fragment shader rather than by a conversion
pass.

A child whose source cannot change between frames is built once, when the scene
is committed, and costs nothing per frame. Only a child that genuinely moves —
an image on a hardware-buffer handle — rebuilds, and only that shader rebuilds.

One gap, in tgfx rather than here: a child backed by a **multi-plane YUV**
hardware buffer only samples under the default `tx`/`ty` of `"clamp"`. Ask for
`"repeat"`, `"mirror"` or `"decal"` on such a child and it paints transparent
instead of tiling. An RGBA image child tiles under every mode.
</Owned>

## Performance notes

- The transpile result is cached by source text, so passing the same string every
  render costs one parse for the life of the process. Build sources as module
  constants rather than interpolating them per render.
- Two shaders with identical source share one compiled GPU program.
- Uniform count and sizes are part of the program key. Changing the *shape* of
  your uniforms recompiles; changing their values does not.
