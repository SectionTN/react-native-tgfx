## Two ways a value can change

A prop takes either a plain number or a Reanimated `SharedValue`. Which you pass
decides which thread pays for the animation.

<Owned by="js">
**A plain value that changes.** Your component re-renders, the reconciler diffs,
the scene is recompiled and re-encoded, and the new buffer crosses to native.
Correct, and fine at interaction rates. At 60 fps it is 60 of those a second.
</Owned>

<Owned by="native">
**A `SharedValue`.** At compile time the value's position in the buffer is
recorded as a *slot*. Reanimated writes the current numbers into a flat array on
the UI thread, and the renderer resolves slots against it as it draws. No
re-render, no re-encode, no buffer crossing.
</Owned>

```tsx
import { useEffect } from 'react'
import { useSharedValue, withRepeat, withTiming } from 'react-native-reanimated'
import { Canvas, Circle } from 'react-native-tgfx'

function Pulse() {
  const r = useSharedValue(20)

  useEffect(() => {
    r.value = withRepeat(withTiming(60, { duration: 900 }), -1, true)
  }, [r])

  return (
    <Canvas style={{ width: 200, height: 200 }}>
      <Circle cx={100} cy={100} r={r} color="#d98a4a" />
    </Canvas>
  )
}
```

`r` is never read on the JS thread after the first commit.

## Which props animate

These resolve through a slot and animate:

- shape geometry — `x`, `y`, `width`, `height`, `cx`, `cy`, `r`, `rx`, `ry`, and
  the `Line` endpoints `x1`, `y1`, `x2`, `y2`
- `opacity` and `strokeWidth`
- `Text`'s `fontSize`
- `Group` transform operands
- shader uniform components

Everything else is read once at commit. `color` is still *typed* `Animated<…>`,
so it accepts a `SharedValue` without complaint and then never moves. `text`,
`path` and `Image`'s `image` used to have the same problem and are now typed as
what they are, so passing a `SharedValue` is a type error rather than a silent
freeze.

| prop | why it freezes |
| --- | --- |
| `color` | packed to a single integer at compile time |
| `Image`'s `image` | a native handle, resolved once |
| `text` | interned into the string table |
| `path` | parsed once into a native path object |
| `fontFamily` | plain `string`, resolved once |
| gradient `colors` and `positions` | written as literals |
| gradient geometry — `start`, `end`, `center`, `r` | written as literals |
| noise `freqX`, `freqY`, `octaves`, `seed` | written as literals |
| `style`, `strokeCap`, `strokeJoin`, `antiAlias` | packed into the paint flags |

The failure is silent — the prop still accepts the value. If something you expect
to move is frozen, check this table first.

To animate a colour today, cross-fade two shapes with animated `opacity`.

## Opacity has one slot per draw

Each draw command carries a single alpha slot. Nesting two animated opacities —
an animated `<Group opacity>` around an animated shape — cannot be represented,
so their product freezes at the last commit. The compiler warns:

```
[tgfx] two opacities in one chain, at least one animated: a draw command has a
single alpha slot, so their product is frozen at the last commit. Animate one
opacity per chain.
```

It fires once per process.

## useClock

`useClock()` returns **seconds** since the first frame as a `SharedValue`,
written on the UI thread. It is the intended driver for time-based shaders:

```tsx
import { Canvas, Fill, Shader, useClock } from 'react-native-tgfx'

const source = `
uniform float2 uSize;
uniform float uTime;
half4 main(float2 pos) {
  float2 uv = pos / uSize;
  return half4(half(0.5 + 0.5 * sin(uTime + uv.x * 6.0)), half(uv.y), 0.6, 1.0);
}
`

function Sweep() {
  const t = useClock()
  return (
    <Canvas style={{ width: 300, height: 300 }}>
      <Fill>
        <Shader source={source} uniforms={{ uTime: t, uSize: [300, 300] }} />
      </Fill>
    </Canvas>
  )
}
```

<Owned by="native">
Seconds rather than milliseconds is deliberate. GLSL ES `mediump` floats stop
being representable above 65504, so a millisecond clock turns every shader that
reads it black after about a minute of uptime, silently. Seconds buy eighteen
hours.
</Owned>

Driving a uniform from `setInterval` instead re-encodes the entire scene on every
tick. It works, and it is the thing this library exists to avoid.

## Changing a value once, without React

`SharedValue`s are for values that *keep* moving. For a value that changes once —
from a tap, a gesture, a network reply — take a handle on the node instead:

```tsx
import { Button } from 'react-native'
import { Canvas, RoundedRect, useNode } from 'react-native-tgfx'

function Box() {
  const box = useNode()

  return (
    <>
      <Canvas style={{ width: 300, height: 200 }}>
        <RoundedRect ref={box} x={20} y={20} width={70} height={50} r={12} color="#4F8EF7" />
      </Canvas>
      <Button title="move" onPress={() => box.set({ x: 120 })} />
    </>
  )
}
```

`set()` never re-renders: no component render, no reconciler commit, no Fabric
commit.

<Owned by="native">
**A prop with a slot** — everything in the list above — is patched in place. A
handled node is compiled with a slot for every one of them it carries, so even
the first write is a single `setValues`: no re-encode, and the render thread
picks it up on the next frame.

`opacity` is the exception: it is made live by the first write to it, not by the
`ref`, because whether it is live is what decides if an enclosing `<Group opacity>`
freezes (see above). A `ref` never changes how a scene composites on its own.
</Owned>

<Owned by="js">
**A prop without one** — `color`, `path`, `text`, `image`, or a slot prop the
element does not carry — re-encodes the scene on every write. Still cheaper than `setState`, since React does no work at all,
but it is the same re-encode the compiler does on a commit.
</Owned>

Handles work on `<Group>` too, so a transform can be driven the same way.

### From a worklet

`set()` is a worklet. Called on the UI thread it writes the slots directly, so a
gesture drives the canvas without the JS thread being involved at all:

```tsx
import { Gesture, GestureDetector } from 'react-native-gesture-handler'
import { Canvas, Circle, useNode } from 'react-native-tgfx'

function Dot() {
  const dot = useNode()
  const pan = Gesture.Pan().onUpdate((e) => {
    'worklet'
    dot.set({ cx: e.x, cy: e.y })
  })

  return (
    <GestureDetector gesture={pan}>
      <View>
        <Canvas style={{ width: 300, height: 200 }}>
          <Circle ref={dot} cx={150} cy={100} r={16} color="#FFCC00" />
        </Canvas>
      </View>
    </GestureDetector>
  )
}
```

<Owned by="native">
A handled node gets its slots at compile time for every patchable prop the
element carries — `cx` and `cy` above — so the first write from a worklet is
already a slot write. The write wakes the same UI-thread mapper that drives
`SharedValue` props, and the renderer picks it up on the next frame.
</Owned>

A write a worklet cannot serve — a colour, a prop the element does not carry, the
first `opacity` — hops to the JS thread through `runOnJS` and re-encodes there,
one frame later. Keep gesture-driven props in the patchable list and in the JSX.

### The next React commit wins

An imperative write lasts until the canvas re-renders. The commit recompiles from
the JSX props, and anything written since the last one is dropped — the element
tree stays the single source of truth, and a stale imperative value can never
outlive the render that contradicts it.

So drive a given value from one side or the other. A value you write with `set()`
should not also be interpolated into the JSX; give the element its initial value
and leave it alone.

`CanvasHandle.redraw()` is the escape hatch for state the scene *points at*
rather than holds — an image handle re-pointed at new pixels, say. `set()`
already redraws on its own.
