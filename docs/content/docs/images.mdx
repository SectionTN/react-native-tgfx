[`Image`](/api/functions/Image) takes the source directly — a `require()`'d
asset, a web URL, a file path, SVG markup, or base64 — and handles decoding,
registration and readiness itself:

```tsx
import { Canvas, Image } from 'react-native-tgfx'

<Canvas style={{ width: 300, height: 400 }}>
  <Image source={require('./cat.png')} x={0} y={0} width={300} height={200} fit="cover" />
  <Image source="https://picsum.photos/300/200" x={0} y={200} width={300} height={200} />
</Canvas>
```

It draws nothing until the decode lands (a web URL is fetched as bytes and
decoded natively — nothing is base64'd in JS), and a failed load warns and
stays empty. One trade, stated plainly: it is a function component, so a
canvas containing one reconciles through React instead of the direct-node
fast path. Irrelevant for typical scenes; for hundreds of animated nodes,
[`TgfxImage`](/api/variables/TgfxImage) is the power form — a plain host tag
taking an already-loaded handle:

```tsx
import { Canvas, TgfxImage, useImage } from 'react-native-tgfx'

const photo = useImage(require('./cat.png'))

photo != null && (
  <TgfxImage image={photo} x={0} y={0} width={300} height={200} fit="cover" />
)
```

</Tab>
<Tab value="Imperative">

```ts
import { image, loadImage } from 'react-native-tgfx'

const photo = await loadImage(require('./cat.png'))

scene.add(image({ image: photo, x: 0, y: 0, width: 300, height: 200, fit: 'cover' }))
```

</Tab>
</Tabs>

[`useImage`](/api/functions/useImage) returns [`TgfxImage`](/api/interfaces/TgfxImage) or `null`.
[`useImageState`](/api/functions/useImageState) returns [`ImageState`](/api/interfaces/ImageState) with `loading` and `error`.
[`loadImage`](/api/functions/loadImage) is the promise form. SVG sources decode to a resolution-independent picture that replays at whatever size it's drawn, not a fixed-resolution raster.

[`ImageProps`](/api/interfaces/ImageProps) · [`Fit`](/api/type-aliases/Fit) · [`Sampling`](/api/type-aliases/Sampling)

A `require()`d asset works in both build types. A release Android build compiles
it into a drawable or raw resource rather than shipping a file, so the source
resolves to a resource name; that name is read natively, and the bytes still
never cross into JS. Two assets whose file names differ only by extension —
`logo.png` beside `logo.webp` — collide as one Android resource, so give them
distinct names.

## SVG documents

A whole SVG document — multiple shapes, fills, strokes, gradients, groups,
`viewBox` scaling — loads through the same sources as any other image, and
draws through [`ImageSVG`](/api/variables/ImageSVG):

<Tabs items={['Declarative', 'Imperative']}>
<Tab value="Declarative">

```tsx
import { Canvas, ImageSVG, useImage } from 'react-native-tgfx'

const icon = useImage(require('./logo.svg'))
const dot = useImage('<svg viewBox="0 0 24 24"><circle cx="12" cy="12" r="10" fill="#0a84ff"/></svg>')

<ImageSVG image={icon} x={0} y={0} width={96} height={96} />
<ImageSVG image={dot} x={104} y={0} width={96} height={96} />
```

</Tab>
<Tab value="Imperative">

```ts
import { imageSvg, loadImage } from 'react-native-tgfx'

const icon = await loadImage(require('./logo.svg'))
const dot = await loadImage('<svg viewBox="0 0 24 24"><circle cx="12" cy="12" r="10" fill="#0a84ff"/></svg>')

scene.add(imageSvg({ image: icon, x: 0, y: 0, width: 96, height: 96 }))
scene.add(imageSvg({ image: dot, x: 104, y: 0, width: 96, height: 96 }))
```

</Tab>
</Tabs>

Markup is recognised by its opening `<`, so a document built in JS needs no
`data:` URI and no base64 — it crosses as UTF-8 bytes and is parsed natively.

`<ImageSVG>` is `<TgfxImage>` under a Skia-compatible name, not a second node kind.
The document is parsed once, at load, into a picture the renderer *replays* at
draw resolution, so it is already an image handle by the time a scene sees it —
which is why `width`/`height` are a destination rather than a raster size, and
why a 24pt icon drawn at 240pt is redrawn rather than blown up. `<Path>` remains
the right thing for a single `d` string; this is for a document.

## Colour profiles

An embedded ICC profile is read at decode and honoured on draw. A photo tagged
Adobe RGB, ProPhoto or Rec.2020 is converted into the canvas's own space rather
than having its numbers reinterpreted, so it looks the same on an `srgb` canvas
as on a `display-p3` one — a browser does the same thing.

Converting into sRGB is a real conversion, not a no-op: out-of-gamut colour is
clipped, which is the correct and unavoidable answer for a display that cannot
show it. A [`colorSpace="display-p3"` canvas](/api/interfaces/CanvasProps) keeps
it instead.

An image with no profile at all — or with one the decoder cannot parse — is read
as **sRGB**, silently. That is the web's default and what the conversion
substitutes for an untagged source, so it is a definition rather than a
correction: nothing has to re-tag the image for it to hold.

<Callout type="warn">
  On iOS, PNG and JPEG decode through ImageIO rather than through tgfx's own
  readers, and ImageIO renders into an sRGB bitmap. A wide-gamut source is
  therefore flattened at decode on iOS, before any canvas sees it, and a P3
  canvas cannot recover what was already clipped. Android reads the profile and
  converts at draw, as described above. Closing the gap means having the Apple
  codec report the `CGImage`'s own colour space — a change in tgfx itself.
</Callout>

## Derived images

These transforms are native-side and reuse the decoded source instead of
decoding the original file again.

```ts
const thumb = photo.scaled(200, 200)
const sprite = sheet.subset(0, 0, 64, 64)
const upright = photo.oriented('rightTop')
const frosted = photo.blurred(20, 20)
```

`oriented` takes an [`Orientation`](/api/type-aliases/Orientation) — the EXIF
tags `topLeft`/`topRight`/`bottomRight`/`bottomLeft`/`leftTop`/`rightTop`/`rightBottom`/`leftBottom`,
naming where the stored top-left pixel belongs.

[`useDerivedImage`](/api/functions/useDerivedImage) does the same as a hook ([`Derivation`](/api/type-aliases/Derivation)).

```tsx
const thumb = useDerivedImage(photo, { type: 'scaled', width: 200, height: 200 })
```

## Encode and save

Any image handle encodes to bytes or writes itself to disk — including a
`renderToImage` result, which completes the headless flow:

```ts
const bytes = await image.encode('webp', 90)   // zero-copy ArrayBuffer, for upload
await image.save(`${dir}/thumb.jpg`, 'jpeg', 85) // written natively; bytes never enter JS
```

`format` is `'png'` (default), `'jpeg'`, `'webp'`, or `'raw'` (straight-alpha
RGBA rows). A derived image encodes what it draws. A disposed handle and a live
camera or video frame reject — a stream has no still to encode.

## Native buffers

[`imageFromNativeBuffer`](/api/functions/imageFromNativeBuffer) wraps a camera or
decoder buffer without a copy ([`PixelFormat`](/api/type-aliases/PixelFormat)).
The producer's reference still has to be released after tgfx retains the
buffer; prefer [`useCameraFrame`](/api/functions/useCameraFrame) for frame
lifecycle management.

```tsx
let frameImage: TgfxImage
const buffer = frame.getNativeBuffer()
try {
  frameImage = imageFromNativeBuffer(buffer.pointer, 'bt601-limited')
} finally {
  buffer.release()
  frame.dispose()
}

// Draw with frameImage, then dispose it when the stream ends.
```

## Decoded pixels

[`imageFromPixels`](/api/functions/imageFromPixels) wraps premultiplied RGBA a
producer computed rather than loaded, e.g. an ML model's output. `rowBytes` is
the stride in bytes, a multiple of 4, tightly packed when omitted.

```tsx
const image = imageFromPixels(pixels, width, height)
```

A buffer another native module produced and owns is borrowed rather than
copied, and the handle keeps that memory alive — so do not write into it while
the handle still points at it. An `ArrayBuffer` constructed in JavaScript is
always copied: JS owns that memory and can detach or collect it at any time.

Like a camera frame, such a handle is a surface to draw, not a source to
derive from: `subset`, `scaled`, `oriented`, `blurred`, `encode` and `save`
throw on it.

For a stream, mint once and re-point that handle with
[`setPixels`](/api/interfaces/TgfxImage#setpixels) rather than creating one per
frame - the same shape as `setNativeBuffer`:

```tsx
if (image != null) {
  image.setPixels(pixels, width, height)
} else {
  image = imageFromPixels(pixels, width, height)
}
```

## Cache

```tsx
setImageCacheLimit(32 * 1024 * 1024)
```

The default decoded-image budget is 64 MB. The limit is applied to both the
decoded-pixel cache and the tgfx GPU resource cache.

## Video

[`useVideo`](/api/functions/useVideo) gives a [`Video`](/api/interfaces/Video)
whose `currentFrame` can be passed straight to `<TgfxImage>`. It requires
Reanimated and Worklets because frames are pulled from a UI-thread frame
callback.
[`loadVideo`](/api/functions/loadVideo) is the promise form outside React — it
resolves the raw native player, not a `Video`, so the caller drives
`updateFrame()` and `release()` itself.

Its second argument is a [`VideoOptions`](/api/interfaces/VideoOptions):

<Tabs items={['Declarative', 'Imperative']}>
<Tab value="Declarative">

```tsx
useVideo(require('./clip.mp4'), {
  seek: 1500,     // jump to 1.5s; seeks again whenever this changes
  paused: false,  // plays as soon as it's open (the default)
  looping: true,
  volume: 0.5,    // 0 to 1, defaults to 0 — a canvas video is usually decoration
})
```

</Tab>
<Tab value="Imperative">

```ts
const player = await createVideoPlayer(require('./clip.mp4'), {
  seek: 1500,     // jump to 1.5s; seeks again whenever this changes
  paused: false,  // plays as soon as it's open (the default)
  looping: true,
  volume: 0.5,    // 0 to 1, defaults to 0 — a canvas video is usually decoration
})

// currentFrame is a one-time snapshot at add time — build the node per frame:
player.onFrame((frame) =>
  scene.add(image({ image: frame, x: 0, y: 0, width: 1280, height: 720 }))
)
```

</Tab>
</Tabs>
