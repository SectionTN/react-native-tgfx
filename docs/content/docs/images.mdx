An image reaches the scene as a `TgfxImage` **handle** — a small integer on the
wire, never bytes. `<Image>` draws it; [`<ImageShader>`](#imageshader) uses it as
a paint source for any other shape.

## Image

`image` is a `TgfxImage` handle from [`useImage`](#useimage) — a small integer on
the wire, never bytes.

`fit` is the full Skia set, default `'contain'`:

| fit | what it does |
| --- | --- |
| `'contain'` | scales down to fit inside the box, letterboxed |
| `'cover'` | fills the box, cropping the source |
| `'fill'` | stretches to the box, ignoring aspect ratio |
| `'fitWidth'` | matches the box width, cropping vertically if needed |
| `'fitHeight'` | matches the box height, cropping horizontally if needed |
| `'none'` | native size, centred |
| `'scaleDown'` | like `'fill'`, but never enlarges |

As in Skia, `cover` crops the *source* rather than overflowing the destination,
so nothing is ever drawn outside the box.

`sampling` is `'nearest' | 'linear' | 'mipmap'`, default `'linear'`. Use
`'mipmap'` when a large image is drawn into a much smaller box — it builds the
mip chain, which `'linear'` alone does not.

`rect` is a source sub-rect in image pixels, so a sprite sheet is drawn without
slicing it in JS:

```tsx
<Image
  x={0} y={0} width={60} height={60}
  image={sheet}
  rect={{ x: 32, y: 0, width: 32, height: 32 }}
  sampling="nearest"
/>
```

## ImageShader

An image as the paint source for any shape — textured fills, image-backed masks,
tiled patterns:

```tsx
import { Circle, ImageShader, useImage } from 'react-native-tgfx'

const photo = useImage(require('./cat.png'))

photo != null && (
  <Circle cx={60} cy={60} r={50}>
    <ImageShader image={photo} rect={{ x: 10, y: 10, width: 100, height: 100 }} fit="cover" />
  </Circle>
)
```

`tx` and `ty` are `'clamp' | 'repeat' | 'mirror' | 'decal'`, both defaulting to
`'clamp'` — the tile mode outside the image's own bounds. `sampling` is the same
set as `<Image>`. `rect` is the destination rect the image is mapped into with
`fit`; omit both to sample the image 1:1 in canvas space, which is what tiling
usually wants.

## Hooks

### useImage

```tsx
const image: TgfxImage | null = useImage(require('./cat.png'))
```

Takes `number | string` — a `require()` asset, an `http(s)`, `file:`, `data:`,
`asset:` or `content:` URI, or a raw base64 string. Returns a native image
handle, or `null` until it is ready.

The handle carries `width`, `height` and a `dispose()`. The draw program only
ever carries its integer id, so a scene's string table does not grow with the
image bytes on screen and a re-commit costs no hashing and no decode.

A local file (`file:` URI, or a bundled asset that resolves to a path) is opened
and decoded natively — its bytes never enter JS. A remote or Metro-served URI
still goes through `fetch`, but as an `ArrayBuffer`; nothing is base64-encoded on
the JS thread. Every path decodes on a background thread, so no frame waits on a
decode. PNG, JPEG and WebP all decode on both platforms, and an SVG document is
parsed and drawn on the same paths — see [SVG documents](#svg-documents).

A photo shot in portrait draws the right way up: the EXIF orientation marker is
read during the decode and the image is oriented before anything measures it, so
`image.width`/`height` are the dimensions you see rather than the ones on disk.

Which decoder does that differs by platform, and the answer only matters when
something goes wrong. Android decodes PNG, JPEG and WebP with tgfx's own codecs,
in-process — not `BitmapFactory` behind JNI — and anything else (HEIF, AVIF) with
the platform decoder. iOS decodes WebP in-process and everything else through
ImageIO.

JPEG and WebP carry their orientation on every one of those paths. A PNG is the
exception: tgfx's own PNG decoder does not read the `eXIf` chunk, so a PNG that
has one draws unrotated on Android and rotated on iOS. Almost nothing writes it —
cameras produce JPEG or HEIF — but if you are generating PNGs, bake the rotation
into the pixels.

The handle is disposed when the source changes or the component unmounts.

### useImageState

```tsx
const { data, error, loading } = useImageState(source)
```

Returns `ImageState`: `data: TgfxImage | null`, `error: Error | null`,
`loading: boolean`. `data` is cleared the moment `source` changes, so a slow or
failing load never leaves the previous image on screen.

### SVG documents

```tsx
const icon = useImage(require('./logo.svg'))
```

There is no separate SVG hook, node or wire format: an SVG **document** is just
another image source. `useImage`, `useImageState` and `loadImage` all take one,
and `<Image>` and `<ImageShader>` draw the handle like any other.

It is recognised from its bytes rather than its file extension, so a bundled
asset, a `file:` path and an `http(s)` URL all reach the parser on their own, and
a `.svg` served with the wrong MIME type still works.

**Its size is nominal, not a resolution cap.** The handle reports the size the
document itself asks for — a 24×24 icon reports 24×24 — but that is not a size it
was flattened to. The document is parsed once into a picture that is replayed at
whatever size it is drawn, so one handle stays crisp at 24 px and at 240 px.
There is no size to pass and none to keep in sync with your layout.

The cost sits where it usually belongs: the picture is replayed per draw rather
than cached as pixels. Right for an icon; worth knowing for a large document
redrawn every frame.

Malformed markup, a non-`<svg>` root, or a document with no resolvable size
rejects the load — `useImageState().error` rather than a crash or a blank draw.

**Text inside an SVG** renders through the same faces `<Text>` can see: whatever
[`loadFont`](/docs/text#loadfont) has registered, plus the system fonts. A
`font-family` naming something neither has does not render at all — register the
face first, or convert the text to paths when authoring the file.

`<Path d="…" />` is a different thing and still the right one for a single shape:
it takes SVG *path data*, takes its fill and stroke from the node's own props,
and involves no document and no parser.

### imageFromNativeBuffer

```tsx
const frameImage = imageFromNativeBuffer(
  frame.getNativeBuffer().pointer,
  'bt601-limited'
)
```

Wraps a platform hardware buffer — an `AHardwareBuffer*` on Android, a
`CVPixelBufferRef` on iOS — as an image handle. Zero-copy and synchronous: the
buffer is imported straight to a GPU texture through
`tgfx::Image::MakeFrom(HardwareBufferRef, YUVColorSpace)`, with no decode and no
CPU round trip.

`format` is `PixelFormat`: `'rgba'` for a single-plane surface, or one of
`'bt601-limited'` (the camera default), `'bt601-full'`, `'bt709-limited'`,
`'bt709-full'`, `'bt2020-limited'`, `'bt2020-full'`, `'jpeg-full'`.

For a stream of frames, keep the handle and call `image.setNativeBuffer(...)` per
frame: the scene keeps referencing the same id, so nothing is re-committed and an
undrawn frame is superseded by the next rather than queued behind it. Such a
handle is not accounted against the decoded-pixel budget — the memory belongs to
whoever produced the buffer.

It is a worklet, so a VisionCamera frame processor can call it directly — the
buffer is only alive for the duration of the callback.

`pointer` is a **raw pointer and nothing can validate one**: a stale value does
not throw, it imports whatever memory is now at that address. If your buffers
arrive as camera frames, use [`useCameraFrame`](/docs/camera#quick-start)
instead — it owns the whole lifetime and the pointer never leaves its scope.
This function is the escape hatch for producers that are not frame objects. See
[camera frames](/docs/camera) for both, and for how `<CameraFrame>` draws them.

### loadImage

```tsx
const image = await loadImage(require('./cat.png'))
```

The same load without React — same sources, `.svg` included. Unlike the hooks,
the caller owns the handle and must `dispose()` it.

### setImageCacheLimit

```tsx
setImageCacheLimit(32 * 1024 * 1024)
```

Byte budget for decoded pixel buffers held between draws — a real LRU keyed on
the handle, defaulting to 64 MB. An image the budget drops is re-decoded on next
use, never lost. Decoded GPU textures are bounded separately by the tgfx context
cache limit (192 MB).
